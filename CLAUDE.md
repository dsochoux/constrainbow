# Constrainbow

Daily word-puzzle web game, live at constrainbow.com. Written entirely by Danny (started Jan 2025). Flask backend + vanilla-JS ES-module frontend bundled with esbuild. Puzzles are pre-generated offline by a Python solver and served as static JSON.

Detailed notes (read these before making changes):
- [docs/gameplay.md](docs/gameplay.md) — rules, both modes, UI behavior, what a play session feels like
- [docs/architecture.md](docs/architecture.md) — every file, data formats, request flow, generator algorithm, deploy
- [docs/findings.md](docs/findings.md) — bugs, risks, tech debt, and improvement ideas found during the Nov 2026 review

## Quick facts
- Run locally: `env/bin/python project/app.py` from the repo root (port 5001). App uses paths relative to the repo root (`./games`, `./word_files`, `./logs`), so it **must** be started from the root. `.claude/launch.json` has a `constrainbow` config for the browser preview.
- The template loads **`project/static/js/bundle.js`**, not the ES-module sources. After editing any JS, rebuild:
  `esbuild ./project/static/js/script.js --bundle --minify --outfile=./project/static/js/bundle.js`
  (`script.min.js` is a stale, unused artifact.)
- Puzzles: the **server generates its own** with a nightly cron job (`scripts/ensure_games.py`, keeping 30 days ahead for all three modes, never overwriting). Locally: `env/bin/python scripts/ensure_games.py [--days N]` from the root. The generator uses in-memory bitsets over `words.txt` (~0.15 s/puzzle); `database.db` is no longer needed. Full explanation: [docs/generation-algorithm.md](docs/generation-algorithm.md).
- Deploy: `./deploy.sh` (scp to `root@constrainbow.com`; rsyncs games both ways with `--ignore-existing`; runs ensure_games and (re)installs the cron line; installs `server/constrainbow.service` and `systemctl restart constrainbow`; reloads nginx; also writes `.gz` copies of style.css, eggs.css and bundle.js, which nginx serves pre-compressed from `/static/`, see `server/nginx-static.conf`). It asks two y/n questions first; `printf 'y\ny\n' | ./deploy.sh` answers both.
- SOLVE mode (🔑, single-solution puzzles, the first tab and the default for new visitors): daily puzzles in `games/solve/MMDDYYYY.json`, made by `ensure_games.py` along with speed/score (via `generate_solve_day` in `scripts/generate_unique.py`), 5 given letters each, answers only from `word_files/common_words.txt` (rebuilt by `scripts/build_common_words.py`) and not reused within 90 days. Hand-picked answers per date go in `word_files/solve_themes.json` (`{"2027-10-31": ["..."]}`, or `{"2026-11-26": {"words": [...], "clue": "...", "emoji": "🦃", "title": "HAPPYTURKEY!"}}` for a clue box above the board, emojis that fall instead of confetti (a list cycles), and a message of exactly 12 characters the CONSTRAINBOW title turns into on a win). Danny writes the themes; find working sets with `--pool w1 w2 ... --day YYYY-MM-DD` (every set of four, for that exact date; full process in docs/gameplay.md, "Themed SOLVE days"). Test single sets with `--words a b c d`, and play any day's puzzle (past or future) at the unlisted `/solve/day?d=YYYY-MM-DD`, which has ‹ › for the days around it, saves progress apart from the daily game and logs nothing. A date within 30 days already has a puzzle that nothing overwrites: regenerate it with `--day YYYY-MM-DD` and replace the server's copy too (deploy's rsync skips existing files). Check that no nearby day reuses a themed word (90-day rule). Easter-egg styles live in `project/static/css/eggs.css` (loaded after style.css). Generated (non-themed) puzzles get at most one easter-egg word; the generator reads the egg words from the `word === '...'` lines in `Word.setRowState` (word.js), so keep each egg in that form. The play-test batch lives at `/solve/test?p=N` (`games/solve-test/`). Logs: `logs/MMDDYYYY/solve.csv`. Design notes and play-test results: docs/findings.md (feature 5).
- Word lists: `word_files/words.txt` (the big list, every accepted word) and `common_words.txt` (the small list, SOLVE answers). Decide reported words and small-list membership on the local-only page `http://localhost:5001/review-words` (`project/word_review.py`, registered only when app.py runs directly, answers only 127.0.0.1, not deployed). Download the server's reports first: `scp root@constrainbow.com:/srv/constrainbow/word_files/reported_missing_words.txt word_files/`. Adding words can give an upcoming SOLVE puzzle a second answer: run `env/bin/python scripts/check_solve_unique.py --fix`, then replace the remade days on the server (deploy never overwrites games). New words also raise speed/score solution counts and sometimes the max score: run `env/bin/python scripts/recount_games.py` (today onward) and copy the changed files to the server too. Restart the local app to make the game accept new words.
- Analytics: the page sends anonymous events (random `playerId` per browser, no IPs) to `/log-event` → `logs/events/YYYY-MM-DD.jsonl`; Danny's dashboard is `/dashboard` (`project/dashboard.py`), password-protected by nginx on the server (`server/nginx-dashboard.conf`; user `danny`, password set by Danny with the command in that file) and open locally. Event logging began 2026-11-16, so visitor numbers start then; finishes come from the CSVs back to 2025. A visit is "new" only if the browser has no `playerId`, `solveTester` or `visited`. Player feedback (the "Send feedback" form on the how-to-play popup's last step) goes to `/feedback` → `logs/feedback.jsonl` and shows on the dashboard; Danny replies from any email when a player leaves one. To track a video, link to `constrainbow.com/?utm_source=<name>`. To see real data locally: `rsync -az root@constrainbow.com:/srv/constrainbow/logs/ logs/` (logs/ is git-ignored).
- Accounts and friends (branch `accounts-friends`, 2026-11-23, not deployed): optional username + password (no email, no reset), mutual friends by link, and a 👥 scoreboard of today's results that stays 🔒 per mode until you finish it. Server: `project/accounts.py` (SQLite at `data/constrainbow.db` plus `data/secret_key`, both git-ignored and never committed); page: `account.js`, `friendsPopup.js`. Delete `data/constrainbow.db` to start over locally. The server backs the database up nightly to `data/backups/` (`scripts/backup_accounts.py`), and every deploy copies those to the local `backups/` (git-ignored). Delete an account on request with `scripts/delete_account.py USERNAME`, run on the server as the `constrainbow` user (see architecture.md). Details: docs/architecture.md ("Accounts") and gameplay.md ("Friends and accounts").
- Game day boundary is midnight **America/New_York**; game id format is `MMDDYYYY`.
- Production: the app runs from `/srv/constrainbow` as the sandboxed systemd service `constrainbow` (unprivileged user, gunicorn on 127.0.0.1:5001 behind nginx). Every file it serves must be world-readable; deploy.sh handles that. Details in [docs/architecture.md](docs/architecture.md).
- Link previews (2026-11-17): `/solve`, `/speed` and `/score` (and `/`, which redirects) carry Open Graph tags (in `head.html`, switched on by `preview_url` in `game.html`) pointing at `static/preview/constrainbow.png?v=N`; bump `preview_version` in head.html when the image changes, since apps cache cards for days. Designs live in `design/og-preview.html` (render a card with headless Chrome at 1200×630, `?only=<id>`). The unlisted `/preview-test?v=N` serves `static/preview/test-N.png` for trying designs in Messages (a new N each time, as Messages caches per link); remove it when done. Messages only shows a card when the link is the whole message, so shared results (text + link) show none there; Discord, Slack, WhatsApp and Telegram do show it.
- The public `/solvelog`, `/speedlog`, `/scorelog` and `/solvetestlog` pages are gone (2026-11-16); use `/dashboard`.
- As of 2026-11-16, games exist through 2026-12-31 locally (committed) and the server keeps 30 days ahead on its own. The live site matches the latest commit: `/` always redirects to `/solve`, share text starts with the mode's link (`constrainbow.com/solve`), the how-to-play example is yesterday's SOLVE answer, themed SOLVE days can drop emojis instead of confetti (Thanksgiving 11/26 is the first, also on the server), `/solve/day?d=YYYY-MM-DD` serves any day's SOLVE puzzle, each daily mode has streaks and a 📊 stats popup (localStorage `stats`, since 2026-11-16), the wordmark links to `/`, a 📅 archive of every past puzzle (`/archive/<mode>`, separate progress and no stats), score mode has SHOW BEST (after finishing; makes the day's score final) and a "Yesterday's best ›" link, the favicon art is centered (icon links carry `?v=2`), the word lists reviewed on 2026-11-16 are deployed (games through 12/31 recounted/remade to match), and the how-to-play fine print reads "Made by Daniel Sochoux. All rights reserved." (Daniel is Danny's professional name, the one on the resume and LinkedIn.)

## Look
"Paper pop" (chosen 2026-11-15 from the three directions in `design/mockups.html`): a cream paper background (`--paper`), ink borders with hard offset shadows, Archivo Black for the wordmark and tiles, Space Grotesk for the UI. Colored tiles get a tint plus a colored shadow plus a shape. Green is kept for winning (typed black tiles flash it, and the title becomes a five-color rainbow that dispenses the confetti). All colors are CSS variables at the top of `style.css`. Rows use ink "links" (`<body class="row-links">`). Favicon sources are in `design/favicon/`. Write American English (color, gray) everywhere.

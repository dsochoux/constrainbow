## Backend — `project/app.py`
Loads `words.txt` into memory at import. Input validation lives at the top: `GAME_ID_PATTERN`, `WORD_PATTERN`, `BOARD_WORD_PATTERN`, `METRIC_PATTERN`, `GAME_MODES`, plus helpers `is_valid_game` and `is_list_of`. Routes:

| Route | Purpose |
|---|---|
| `GET /` | redirect to `/solve` (the default mode) |
| `GET /speed`, `/score` | render game.html with `game_id` (today, Eastern), mode, emojis, date `MM/DD` |
| `GET /game?game-id=&game-mode=` | read `games/{mode}/{id}.json` (modes `solve`, `solve-test` and `solve-day` also return `givens`, `solution` and `emoji` (themed days' falling emojis, else `[]`); `solve-test` takes a 2-digit id from `games/solve-test/`, `solve-day` reads `games/solve/`), return `{game_id, constraints, grid, num_possible_solutions, num_possible_points, words: [all 2,531 words]}`; invalid id/mode or missing file → 404 |
| `POST /report-missing-word` `{words:[...]}` | words must match `[a-z]{5}`, else 400; append to `word_files/reported_missing_words.txt` (flock) |
| `GET /archive`, `/archive/<mode>?m=YYYY-MM` | the archive calendar (`archive.html`): days from `ARCHIVE_START` (2026-11-01, the same for every mode) to before today (Eastern) with a puzzle file; the month is clamped to that range; Sunday-first weeks via `calendar.Calendar`. `/archive` redirects to `/archive/solve` |
| `GET /archive/<mode>/<YYYY-MM-DD>` | a past puzzle on game.html with `is_archive=True` (hidden `#is-archive`), prev/next past days, and SOLVE's givens and clue. Today or later redirects to `/<mode>`, before `ARCHIVE_START` to the calendar; no file → 404 |
| `POST /log-event` `{event, player, mode, game, archive, ...}` | analytics: appends one JSON line to `logs/events/YYYY-MM-DD.jsonl` (Eastern date) with the time and a mobile/desktop guess from the User-Agent. Events and their fields are in `EVENT_FIELDS`: `visit` (new, ref = referring host, utm = ?utm_source, page), `start`, `finish` (seconds / reveals / points, max, words), `share` (solution), `show_best` (points, max), `report` (count). Every field is checked; unknown events or fields → 400. No IPs are stored |
| `POST /feedback` `{message, email, website, player, mode, game}` | the how-to-play popup's feedback form: appends `{date, time, player, mode, game, email, message, device}` to `logs/feedback.jsonl`. Message up to 2,000 characters, email optional (loosely checked). A filled-in `website` (a hidden field only bots fill) is answered 204 and dropped. At most 5 messages per player and 200 in all per Eastern day (429 after that) |
| `GET /dashboard?range=7\|30\|90&day=YYYY-MM-DD` | Danny's analytics (`dashboard.py`, `dashboard.html`): visitors, new/returning, finishes per day (finishes from the CSVs back to 2025), per-mode visited → started → finished → shared for the daily puzzles (plays = player-days, with different players in brackets), referrers and utm tags, devices, a day's submissions and result summaries, SOLVE difficulty estimate vs. real times, pending word reports, feedback messages (newest 50, with a mailto link when the player left an email). On the server nginx asks for a password (`server/nginx-dashboard.conf`) and marks the request with `X-Dashboard-Auth: passed`; through nginx without that it's a 404. Locally it opens without a password. (The old public `/solvelog`, `/speedlog`, `/scorelog`, `/solvetestlog` were removed on 2026-11-16) |
| `GET /best-solution?game-id=` | a score puzzle's `{points, words}` from `best_solution`, for SHOW BEST; 404 for a day that hasn't started yet (Eastern) or a bad id. Only keeps the answer out of the page: anyone can ask for today's |
| `POST /log-solution` `{game_id, mode, metric, words}` | validated (8-digit id, `speed`/`score`, metric `[0-9:/]{1,20}`, words `[a-z-]{5}`), else 400; append `time,metric,w0..w3` to `logs/{game_id}/{mode}.csv` (flock, header on first write) |
| `GET /words` | send words.txt |
| `GET /review-words` (+ `/data`, `POST /decide`) | **local only**: the word review page (`project/word_review.py`, `templates/word_review.html`). Registered only in app.py's `__main__` block, so gunicorn never has it; answers only 127.0.0.1/::1 without `X-Forwarded-For`; deploy.sh doesn't copy it. Reported words: reject / big list / big + small / undecided. Big list: on or off the small list. Every change rewrites the lists (sorted, deduplicated) and rechecks upcoming SOLVE puzzles for uniqueness. A word can only leave words.txt if it was reported and isn't a SOLVE answer |
| `GET /solve` | today's SOLVE puzzle (plus `clue`, read from the puzzle file by `get_clue`, for themed days) |
| `GET /solve/day?d=YYYY-MM-DD` | any day's SOLVE puzzle, past or future (unlisted, for trying out themed days), `game_mode="solve-day"`, with ‹ › links to the days around it. 404 if that day has no puzzle; a bad date means today. Progress is saved under `solveDay{MMDDYYYY}`, and solves aren't logged |
| `GET /solve/test?p=N` | SOLVE test-batch puzzle N (unlisted; out-of-range N is clamped), `game_mode="solve-test"`. The old `/playtest?p=N` redirects here |
| `POST /log-solve` `{puzzle, mode, tester, seconds, black_reveals, color_reveals, revealed_tiles, replay, words}` | validated; daily (`mode: solve`) solves go to `logs/MMDDYYYY/solve.csv`, test-batch ones to `logs/solve-test.csv`, with the puzzle's given-letter count. `/log-solution` refuses mode `solve` |
| `GET /preview-test?v=N` | unlisted: a page whose link-preview tags point at `static/preview/test-N.png` (N must exist, else the newest), for trying a design in Messages without touching the real pages. Messages caches a card per link, so each try uses a new N. Remove once the share-sheet experiment (findings.md) is done |
| `GET /favicon.ico` | send `static/favicon_io/favicon.ico` (browsers ask for it at the root) |

Production: nginx 1.26 (HTTPS via Let's Encrypt, auto-renewed by certbot) proxies to gunicorn `-w 4 project.app:app -b 127.0.0.1:5001`. gunicorn runs from `/srv/constrainbow` as the systemd service `constrainbow` (`server/constrainbow.service`). The service runs as the no-login system user `constrainbow`, restarts on crash and starts at boot. It is sandboxed (`ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `NoNewPrivileges`) and may write only to `logs/` and `word_files/reported_missing_words.txt`; everything else under `/srv/constrainbow` is root-owned and read-only to it. gunicorn's output goes to `gunicorn.log`. The nightly root cron runs `ensure_games.py` from `/srv/constrainbow`. No gzip on JSON responses.


Server (checked 2026-11-15): DigitalOcean droplet with 1 vCPU and 1 GB RAM, Ubuntu 24.10, clock in UTC, Python 3.12.7. The venv `env/` was built from `project/requirements.txt` (pinned). `/srv/constrainbow` is not a git checkout. The server's `project/templates/` also holds an old, unused `index.html` from before 2026-11-15. The pre-move folder is kept at `/root/constrainbow-backup-2026-11-15` (contains legacy `generated_games/` and old `gunicorn.log`). The server's `reported_missing_words.txt` is the real one (478 lines on 2026-11-16; the local copy was synced from it that day and every word decided). ufw is inactive; port 5001 is not publicly reachable because gunicorn binds 127.0.0.1. Access: `ssh root@constrainbow.com`. Because the app user isn't root, every file it serves must be world-readable: a root-only `favicon_io/` made every icon 404 after the move, and deploy.sh now runs `chmod -R a+rX` on `project`, `word_files`, `games` and `scripts`.

## Puzzle JSON format
```jsonc
{
  "grid": [[0,1,0,0,3], ...],          // 4×5, constraint id per tile (0 = black/wildcard, 1-4 = red/orange/yellow/blue)
  "constraints": [[[w,l],...], ...],   // index = constraint id, list of [word, letter] positions (index 0 = all black tiles)
  "num_possible_solutions": 70654,
  "num_possible_points": 64,           // max achievable score
  "best_solution": {"points":64,"word_1":"maxim",...}   // NOT sent to client
}
```

## Frontend — `project/static/js`
Entry `script.js` → `new Manager()` on DOMContentLoaded. Class layout:

- **Manager** (`manager.js`) — page controller. Fetches `/game`, builds `accepted_words` Set, instantiates `SpeedBoard` or `ScoreBoard` (score mode then calls `selectFirstBlank()`), wires keydown, virtual keys (dispatch synthetic `KeyboardEvent`), report/copy buttons, `visibilitychange` → pause. Owns keyboard graying (`updateKeyboard`), logging POST, report POST. How-to-play: `setUpHowToPlay` / `showStep` / `showHowToPlay` / `hideHowToPlay`; first visit opens it via `localStorage.visited`. The keydown handler ignores keys typed into an input or textarea (the feedback form).
- **Feedback** (`feedback.js`) — the form on the how-to-play popup's last step: "Send feedback" shows it, SEND posts to `/feedback` (SOLVE test and day pages count as `solve`) and shows Thanks / too many today / check the email.
- **Board** (`board.js`, base) — state: `words[]`, `selectedLetter`, `constraints`, `grid`, `constraintAssignments[4]` (letter per color), `blackLetters{letter:count}`. Handles selection (`selectLetter`, `selectFirstBlank`; `tappedLetter`: a second tap in a row on the same tile deselects it via `deselectLetter`; a tap on a tile the cursor moved to on its own keeps it), navigation (arrows wrap), `handleLetterKeyPressed` (conflict checks → flash + shake conflicting tiles, or fill all tiles of color with one simultaneous pop via `popConstraint` → auto-advance to next blank), backspace, clear, `check()` (invalid words → hide items + report button; all valid → `handleSolutionFound` → log once, celebrate, copy button), `celebrate()` (the title first: `manager.showRainbow(true)` returns each title letter's position, color and hop time, and `launchConfetti` drops pieces from beneath each one; then the board's diagonal wave, starting when the title's wave reaches its last letter), `copyResults()` (emoji grid; second click within 5 s includes words), localStorage save/load (`{prefix}Word{w}` = JSON array of 5 letters).
- **SpeedBoard** — timer (`setInterval` 1 s, persisted as `elapsedSeconds`), play/pause button (START selects the first blank), letters hidden while paused, `speedGameId`/`speedIsSolutionFound` in localStorage.
- **ScoreBoard** — score = sum of `LETTERS_TO_POINTS` over all filled tiles (`scoreGameId`, `scoreIsSolutionFound`). `scoreDayBest` `{points, words}` is the best finished board today; `getSharePoints`/`getShareWords` (used by `Board.copyResults`) share it. SHOW BEST (`askToShowBest` → `#best-overlay` → `showBest`, which fetches `/best-solution`) stores `scoreRevealed` `{final, best}`, builds the read-only `#best-board` from plain tile markup, and `showView` flips between it and `#board`; `isScoreFinal()` makes `Manager.recordResult` stop saving stats. The `/score` route passes `yesterday_best`, which the template puts in a hidden `#yesterday-best` element for the stats popup; the `#yesterday-best-link` at the end of the description opens the popup. `updateScoreDisplay` adds class `over` (red) when the score passes `numPossiblePoints` and shakes the pill the first time. `pause()` is a no-op inherited from Board.
- **Word** / SpeedWord / ScoreWord — 5 Letters inside a `.word-row` element; `updateLetter` tracks fill count, validates against word list when full (`turnRed` shakes and calls `setRowState('invalid')`; valid rows get `'valid'`), writes itself to localStorage.
- **Letter** / SpeedLetter / ScoreLetter — DOM tile (`div.letter.c{n}` > `span.letter-text` [+ `span.letter-points`]); click → board callback; `playAnimation(className, delay)` with `pop`, `shake`, `celebrate`. SpeedLetter adds paused state; ScoreLetter shows point value.
- **Analytics events** — `Manager.logEvent(event, extra)` posts to `/log-event` with `getPlayerId()` (localStorage `playerId`, a random 8-hex id; it reuses the old `solveTester` id, which `/log-solve` also sends). Sent from: `logVisit()` on every game page (referring host, `utm_source`, and new or not: `Manager.isNewPlayer()`, checked in the constructor before the how-to-play popup sets `visited`, counts a browser as new only if it has no `playerId`, `solveTester` or `visited`, so people who played before the event log still count as returning), the archive calendar's inline script (page `calendar`), `SpeedBoard.resume` on the first START (SOLVE too), the first letter on an empty score board, `Board.handleSolutionFound` on the first finish, the COPY RESULTS click, `ScoreBoard.showBest`, and `reportMissingWords`. The SOLVE test batch and `/solve/day` send nothing. Failures are ignored.
- **Link previews** — `game.html` sets `preview_url` for today's puzzle in each mode (not archive, `/solve/day` or `/solve/test`), and `head.html` then adds Open Graph and Twitter tags: title "Constrainbow", description "Same color, same letter. Three ways to play, every day.", image `static/preview/constrainbow.png?v={preview_version}` (1200×630: the wordmark, a partly filled SOLVE / SPEED / SCORE / SHARE board aligned under the C, and that line of text). Bump `preview_version` when the image changes, since apps cache cards for days. `/` redirects to `/solve`, which preview fetchers follow.
- **Keeping storage** — `Manager.keepStorage()` (called from `recordResult`, so after a finish) asks the browser to keep this site's storage when the device runs low on space (`navigator.storage.persist()`), unless it already has. Skipped in Firefox, which would show the player a permission popup. It doesn't stop Safari's 7-day deletion (see findings.md, "Back up progress on the server").
- **Storage prefixes** — `Manager.storagePrefix` is the mode for today's puzzle (`speed`, `score`, so the original keys like `speedWord0`, `scoreGameId` are unchanged; speed's timer stays plain `elapsedSeconds`) and `archive<Mode><MMDDYYYY>` for an archive puzzle. SpeedBoard, ScoreBoard, SpeedWord and ScoreWord build every localStorage key from it. `Manager.isArchive` also turns off logging and stats (`recordResult` instead marks the day in localStorage `archive` for the calendar's ✓) and switches the share text to `getShareLink()` / a date with the year.
- **SolveBoard** / SolveWord / SolveLetter — SOLVE mode, the single-solution puzzles (extend the Speed* classes). Givens and revealed tiles are "locked" (`setGiven`, pressed-in style, can't be typed over or deleted, restored after CLEAR). `reveal()` fills the selected black tile, or the selected tile's whole color, first clearing anything that would clash. Progress is saved under its own keys: the daily puzzle in `solveWord0-3` and `solveState` (which stores the answer, so a new day's puzzle starts fresh), test-batch puzzles in `solveTest{NN}Word0-3` and `solveTest{NN}State`. `initBoard` and `startTimer` are overridden so the daily speed game's `speedWord*`, `speedGameId` and `elapsedSeconds` are never touched. The REVEAL button says what it would fill (via `updateRevealButton`, called from `Manager.updateKeyboard`, `pause` and `resume`): "REVEAL LETTER" on a black tile, "REVEAL N LETTERS" on a color, plain "REVEAL" while paused or on a locked tile, and reveals are counted per tile. Results go to `/log-solve` with a random per-browser `solveTester` id. `getEmojiBoard` marks given letters ⬜ and revealed tiles 💡 in the share grid.
- **Stats** (`stats.js`) — the localStorage `stats` object, `{solve|speed|score: {MMDDYYYY: result}}` (solve `{seconds, reveals}`, speed `{seconds}`, score `{points, max}`). `record(mode, gameId, result, isBetter)` returns true the first time a day is recorded; `getStreaks(mode, todayId)` returns `{current, best}` from consecutive game ids. **StatsPopup** (`statsPopup.js`) renders the 📊 popup: played and streaks plus each mode's `extras` (SOLVE: no-reveal solves, average reveals; SPEED: best time; SCORE: perfect scores) and a bar chart. Once today's puzzle is solved (whenever the page's `#copy-results-button` is showing) it adds its own COPY RESULTS button, which clicks the page's button and mirrors its text through a MutationObserver. `Manager.recordResult()` is called from `Board.handleSolutionFound` with the board's `getStatsResult()`, and opens the popup on a day's first finish; `Manager.getStreakText()` adds `| 🔥 N` to the share text. Only pages with a `#stats-button` (the three daily modes) record.
- **helpers.js** — `LETTERS_TO_POINTS` (duplicated in generate_game.py and hard-coded in game.html keys), constants, cookie helpers, `formatTime`, `delayedForEach`, `launchConfetti(emojis, sources)` (colored paper, or the given emojis on themed days; with `sources` from `Manager.showRainbow`, each title letter drops its own pieces in its color, otherwise they fall from the top of the screen).

## Look — `style.css` ("Paper pop", 2026-11-15)
Chosen from the three directions in `design/mockups.html`.
- **Tokens** at the top of the file: `--ink #1d1b20`, `--paper #fbf4e6`, colors `--c1..--c4` (red `#e0352b`, orange `#ff8a1f`, yellow `#e6c200`, blue `#3a3fd9`) and tints `--t1..--t4`. Fonts: Archivo Black (`--display-font`: wordmark, tiles) and Space Grotesk (`--ui-font`), loaded from Google Fonts.
- **Wordmark**: `h1.wordmark > a[href="/"] > span` ×12. The link holds the 12-column grid, so the gaps between letters are clickable too.
- **Sizing**: `--tile` drives `--content`, the one width the wordmark, mode switch, board and keyboard all share, so nothing hangs over. `--key` and `--key-wide` are derived from `--content`. They're computed on `body` so a body class can change their inputs. Smaller tiles under `max-height: 645px`.
- **Tiles**: ink border plus a hard offset shadow. Colored tiles get a tint, a colored shadow and a shape in `::before` (red circle, orange square, yellow diamond, blue triangle) for color-blind players. The selected tile lifts (`translate(-3px,-3px)`, 6px shadow) and shows a blinking caret (`::after`).
- **Rows**: `<body class="row-links">` joins each word's tiles with ink links (across only, always black). Without the class, rows show as "rails" (a strip behind each word, green when valid, red when invalid).
- **Keys**: `button { all: unset; box-sizing: border-box; }`. `all: unset` also resets box-sizing, so without the second line key borders add to their width and the keyboard overflows. CLEAR and DEL are paper-colored word keys (`.key-word`).
- **Motion**: keyframes for pop, shake, celebrate, `rainbow-in` (the title's win wave) and confetti (`confetti-drop` for pieces dropped by the title); all switched off under `prefers-reduced-motion`. Each Letter animation has its own delay variable (`--pop-delay`, `--celebrate-delay`).
- **Win colors**: `--win` (green) isn't a constraint color. In the board's win wave (`--flash`), black tiles you typed flash green and given ones black; the wordmark's `.rainbow` class adds it to its shadows (`--r`, a 5-color cycle). `Manager.showRainbow` adds the class on a win and on loading a finished puzzle; `playTitleWave(wordmark, text)` plays the wave, swapping each letter to `text` at the top of its hop. On a win, `Board.getTitleMessage()` picks a 12-letter message (the theme's `title` from the puzzle JSON, else SOLVE's NOHELPNEEDED, score's BESTSOLUTION, speed's QUICKESTTIME), and `showRainbow(true, message)` shows it for 3 s before turning back. SolveBoard extends SpeedBoard, so it calls `Board.prototype.getTitleMessage` directly. The keydown handler sends keys the board doesn't take to `listenForSecretWord`, which plays the wave and confetti when the last seven letters spell RAINBOW (`.four-colors` keeps the title's own colors before a win). `Word.setRowState` adds `.slant` to a valid row that spells SLANT (`transform: skewX(-10deg)` on the `.word-row`) and `.askew` to one that spells ASKEW (each tile turned with the separate `rotate` property, which adds to the tiles' own transforms).
- **Favicon**: a rainbow "C" in the four colors. SVG sources are in `design/favicon/` (`D.svg` and `D-full.svg` for the full-square app icons). PNGs were rendered with headless Chrome (`--headless=new --screenshot --default-background-color=00000000`) and resized and packed into the .ico with ImageMagick. ImageMagick's own SVG renderer drops strokes, so don't use it directly. The art (card, offset shadow and C) sits in a `translate(2.25 2.25)` group so the card *plus its shadow* is centered in the square (fixed 2026-11-16; before, home-screen icons sat up and to the left). The icon links in game.html and the manifest carry `?v=N` (`icon_version` in game.html): bump it whenever the icons change, or browsers and home screens keep the old ones.

## Generator — `scripts/generate_game.py`
> Since 2026-11-15 the row checks use in-memory bitsets instead of the SQL queries described below (same results, 86× faster), and `scripts/ensure_games.py` + a nightly server cron keep 30 days of games ahead. See [generation-algorithm.md](generation-algorithm.md) for the full write-up.

`Game(date, mode, num_colored).generate()`:
1. **Layout**: shuffle colors 1–4; row i gets colors (s[i], s[(i+1)%4]) at two random positions (8 colored tiles, guaranteeing a connected cycle). Add `num_colored − 8` more tiles with *distinct* random colors at random empty positions (speed 10, score 9).
2. **Solve**: backtracking over colors 1→4, assigning distinct letters a–z; prune when any row containing that color has no word matching the assigned positions (`SELECT COUNT(*) … WHERE nth_letter = ?`). At a full assignment, for each row query words where colored positions match and black positions ≠ any assigned letter. Solution count += product of per-row counts; best score = sum of per-row maxima (valid because black letters may repeat across rows).
3. Repeat layouts until `num_solutions ≥ threshold` (speed 15k, score 50k), write `games/{mode}/{id}.json` with `best_solution`.
The `__main__` block still loops a hard-coded date range for manual runs; normally `ensure_games.py` is used instead.

Note: count is over (letter assignment × word choices); different assignments can't produce the same 4 words, so it's a true count of distinct boards.

## Deploy — `deploy.sh`
Asks two y/n questions (bundle rebuilt? dev changes removed?), then:
1. scp `app.py`, `game.html`, `head.html`, `archive.html`, `style.css`, `bundle.js`, `favicon_io/*`, `words.txt`, `common_words.txt`, `solve_themes.json` (if any) and the generation scripts to `/srv/constrainbow`. The word review page (`word_review.py`, `word_review.html`) and the list-maintenance scripts are deliberately not copied.
2. rsync games both ways with `--ignore-existing` (never overwrites), run `ensure_games.py`, and (re)install the cron line `15 3 * * * cd /srv/constrainbow && env/bin/python scripts/ensure_games.py >> generate.log 2>&1`.
3. Create the `constrainbow` user if missing; make sure `logs/` and `reported_missing_words.txt` exist and belong to it; `chmod -R a+rX` the read-only folders.
4. Install `server/constrainbow.service`, `daemon-reload`, `enable`, `restart`; reload nginx.

Non-interactive: `printf 'y\ny\n' | ./deploy.sh`. Server-side `reported_missing_words.txt` and `logs/` are never pulled back automatically. Because games are never overwritten, a remade or recounted game (`check_solve_unique.py --fix`, `recount_games.py`, `generate_unique.py --day`) has to be copied to the server by hand, e.g. `rsync -az --files-from=<list> games/ root@constrainbow.com:/srv/constrainbow/games/`.
